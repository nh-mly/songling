# 遥操作 · 详细说明

> 查细节、排故障、调参数用。快速上手见 `遥操作_快速上手.md`。

---

# 一、工作原理

## 1.1 数据流

```
【PC-A · leader】                        【PC-B · follower】
  agx_arm_ctrl                            agx_arm_ctrl
   ├ 读 6 轴 + 夹爪 (200 Hz)               ├ 收目标 (50 Hz)
   │  /leader/feedback/joint_states        │  /follower/control/joint_states
   │            │                          │        │
   │            ▼                          │        ▼
   │      teleop_bridge (50 Hz)            │   move_j(6 个弧度) → CAN
   │      补偿 → 低通 → 限速 → 看门狗        │
   │            │                          │
   └────────────┴──── WiFi / ROS 2 DDS ────┘
```

**只传关节角，不传图像、不传力。**

## 1.2 为什么用关节空间映射

| 方案 | 优点 | 缺点 |
|---|---|---|
| **关节映射（我们用）** | 无计算、无奇异点、延迟低 | 要求两台同构型；末端差几毫米 |
| 笛卡尔映射 | 末端精确一致 | 每帧解 IK，会遇奇异点、解突变 |

两台是同型号同固件（v189），关节 1:1 直接对应最简单可靠。
代价：末端绝对位置有 5–10 mm 偏差（连杆加工误差）。

## 1.3 为什么要走 ROS 桥

SDK 自带主从（`set_leader_mode` 0xFA / `set_follower_mode` 0xFC），但它通过 **CAN 总线**通信，
要求两台臂挂在同一条 CAN 上。这里是两台电脑、两条独立 CAN，CAN 帧过不去。

所以只借"零力拖动"的能力（用物理按键实现），数据通道换成 ROS 2 网络。

# 二、命令详解

## 2.1 CAN 激活

**作用**　设置 `can0` 为 1 Mbit 并拉起来，抓帧确认机械臂在通信。

**前提**　USB-CAN 已插、机械臂已上电、需要 sudo。

**命令**

```bash
sudo ~/107/songlin/scripts/can_up.sh
```

**输出**

```
[1/3] 检查 USB-CAN 模块
[ OK ] 检测到: can0

[2/3] 激活 can0 @ 1000000
  用官方脚本: .../can_config.sh
[WARN] 官方脚本返回非 0,继续用 ip link 兜底
  手动配置 ip link
[ OK ] can0 up,bitrate=1000000

[3/3] 抓帧验证(3 秒)
[ OK ] 20 帧
[ OK ] 检测到状态/关节反馈帧
```

第 2 步那个 `[WARN]` 是**正常的**——官方脚本要求 2 个 CAN 模块，单臂只有 1 个，兜路会成功。

**健康判据**（不需要 sudo）

```bash
for i in 1 2 3; do A=$(cat /sys/class/net/can0/statistics/rx_packets); sleep 3; \
  B=$(cat /sys/class/net/can0/statistics/rx_packets); echo "$((B-A)) 帧/3秒"; done
```

| 结果 | 判断 |
|---|---|
| 约 7000 帧/3秒（2300+ 帧/秒） | ✅ 正常 |
| 几十~几百 | ⚠️ 接触不良 / 电源不稳 |
| 0 | ❌ 未连接 / 未上电 / 接口 DOWN |

**出错**　→ §4 #2 #3 #4

## 2.2 加载环境

**作用**　设 `ROS_DOMAIN_ID=66`、`ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET`，
并加载 ROS 2 与工作区 `install/`。

**前提**　无。**每个新终端都要执行**。

**命令**

```bash
source ~/107/songlin/scripts/teleop_env.sh
```

**输出**

```
[teleop_env] DOMAIN=66  RANGE=SUBNET  WS=/home/nero/107/songlin
```

**自检**

```bash
ros2 pkg prefix piper_teleop
```

必须有输出（`/home/xxx/107/songlin/install/piper_teleop`）。没有就是没加载成功。

> 漏了这一步会同时出现两个问题：**找不到包** + **看不见对方**。

**出错**　→ §4 #1

---

## 2.3 A 机 · role:=leader

**作用**　起驱动 → 清除遗留 Leader 模式 → 使能 → 开控制门闸 → 回零 → 验证 → 提示按键。

**前提**　CAN 已激活；终端已加载环境。

**命令**

```bash
ros2 launch piper_teleop teleop.launch.py role:=leader
```

**输出**

```
当前角度: j1= +2.00 j2= -2.08 j3= +2.25 j4= +2.17 j5=+22.23 j6= +1.11
已规范化:清除遗留的 Leader 模式(0xFC)
使能: Agx_arm enabled
控制门闸: External control gate opened
回零第 1 次: 最大偏差 0.00° (阈值 3.0°)
现在请按下机械臂上的【拖动/示教按键】开启重力补偿
==== leader 准备完成 ====
```

**输出含义**

| 行 | 含义 |
|---|---|
| `当前角度` | 臂上电时的真实姿态（通常不在零位） |
| `已规范化` | 发 `0xFC` 清除上次遗留的 Leader 模式，保证反馈帧正常 |
| `使能` | 电机上力，臂锁位 |
| `控制门闸` | 允许外部指令写入（回零与桥都需要） |
| `回零第 N 次` | 偏差 <3° 视为成功，最多重试 2 次 |
| `准备完成` | 之后每 10 秒打印一次当前角度 |

**回零后的处理**：**用手按下机械臂上的拖动/示教按键**（LED 亮）。
臂变轻、可手拖，反馈帧照常 200 Hz。

**注意**

```
ros2 service call /leader/leader_mode std_srvs/srv/Empty "{}"     ← 禁止
```

`0xFA` 会被控制器持久化，下次上电臂不发 `0x2Ax` 反馈帧，驱动报
`Failed to get firmware version` 并退出。恢复见 §2.7。

**出错**　→ §4 #2 #5 #6

---

## 2.4 B 机 · role:=follower

**作用**　同 2.3，但以 `speed_percent:=60` 运行（跟随需要比手拖端更快）。

**前提**　同上。

**命令**

```bash
ros2 launch piper_teleop teleop.launch.py role:=follower
```

**输出**　同 2.3，末尾为 `==== follower 准备完成 ====`。

**注意**　B **不要**按拖动按键——它要保持刚性才能准确跟随。

**出错**　→ §4 #2 #3 #4

## 2.5 姿态检查

**作用**　确认两台姿态接近。桥是绝对角度镜像，差太多时 B 会高速扫向 A。

**前提**　两台都已"准备完成"。

**命令**（任一台执行）

```bash
python3 - <<'PY'
import math, time, rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState
rclpy.init(); n=Node("cmp")
A,F={},{}
n.create_subscription(JointState,"/leader/feedback/joint_states",lambda m:A.update(dict(zip(m.name,m.position))),10)
n.create_subscription(JointState,"/follower/feedback/joint_states",lambda m:F.update(dict(zip(m.name,m.position))),10)
t=time.time()
while (len(A)<6 or len(F)<6) and time.time()-t<12: rclpy.spin_once(n,timeout_sec=0.1)
if len(A)<6 or len(F)<6: print("读不到数据"); raise SystemExit
mx=0
for i in range(1,7):
    k=f"joint{i}"; d=math.degrees(F[k]-A[k]); mx=max(mx,abs(d))
    print(f"  {k} A={math.degrees(A[k]):+7.2f}  B={math.degrees(F[k]):+7.2f}  差={d:+6.2f}")
print(f"\n  最大差 {mx:.2f}°  {'可以开桥' if mx<15 else '先对齐'}")
PY
```

**输出**

```
  joint1 A=  +0.04  B=  +0.02   差= -0.02
  ...
  最大差 0.05°  可以开桥
```

**判据**　最大差 **<15°** 才能起桥。超过则把 A 拖近 B，或让 B 重新回零。

**出错**　→ §4 #7

---

## 2.6 起桥

**作用**　订阅 A 的关节角，经补偿/低通/限速/看门狗后发布给 B。

**前提**　两台已准备完成、姿态差 <15°、**独立终端**（不能与 launch 共用）。

**命令**

```bash
ros2 launch piper_teleop teleop.launch.py role:=bridge
```

**输出**

```
bridge /leader/feedback/joint_states -> /follower/control/joint_states @ 50 Hz
       max_step=3.00deg/50Hz max_vel=600deg/s alpha=0.40 watchdog=300ms
已对齐,开始转发(TELEOP)
已发 2241 帧 | 跳过 1652 | 本帧滞后 1.26deg
```

**统计字段**

| 字段 | 含义 | 正常 |
|---|---|---|
| `已发 N 帧` | 累计转发（50 Hz） | 持续增长 |
| `跳过 M` | 死区跳过的次数（手不动时增加） | 正常 |
| `本帧滞后` | 目标与限速后指令之差 | **0.1~4°**；>10° 说明拖太快 |

**参数来源**　`install/piper_teleop/share/piper_teleop/config/teleop_params.yaml`

**出错**　→ §4 #7 #8 #9 #10

## 2.7 手工版（封装不可用时）

当 B 机没有 `piper_teleop` 包，或想单步定位时用。

**A 机**

```bash
ros2 launch agx_arm_ctrl start_single_agx_arm.launch.py \
  namespace:=leader arm_type:=piper can_port:=can0 effector_type:=agx_gripper \
  speed_percent:=20 auto_enable:=false control_enabled:=false
```

然后另开终端：

```bash
ros2 service call /leader/enable_agx_arm std_srvs/srv/SetBool "{data: true}"
ros2 service call /leader/control_enable std_srvs/srv/SetBool "{data: true}"
ros2 service call /leader/move_home std_srvs/srv/Empty "{}"
```

**B 机**

```bash
ros2 launch agx_arm_ctrl start_single_agx_arm.launch.py \
  namespace:=follower arm_type:=piper can_port:=can0 effector_type:=agx_gripper \
  speed_percent:=60 auto_enable:=false control_enabled:=false
```

```bash
ros2 service call /follower/enable_agx_arm std_srvs/srv/SetBool "{data: true}"
ros2 service call /follower/control_enable std_srvs/srv/SetBool "{data: true}"
ros2 service call /follower/move_home std_srvs/srv/Empty "{}"
```

**注意**　手工版的 `move_home` 可能报成功但不动作（见 §4 #6），
必要时改用：

```bash
ros2 topic pub --once /leader/control/move_j sensor_msgs/msg/JointState \
  "{name: [joint1,joint2,joint3,joint4,joint5,joint6], position: [0,0,0,0,0,0]}"
```

**恢复被 0xFA 卡住的臂**

```bash
cansend can0 470#FC00000000000000
```

（`0x470#00...` 是空操作，**不能**用来复位）

## 2.8 停止

| 顺序 | 操作 |
|---|---|
| 1 | 桥终端 Ctrl-C |
| 2 | A / B 的 launch 终端 Ctrl-C |
| 3 | A 的拖动按键 LED 若亮 → 按一下关掉（臂锁位） |

不需要发 `restore_drag_mode`：本方案没用 `0xFA`。

# 三、参数

改 `src/piper_teleop/config/teleop_params.yaml`，重编生效。

| 参数 | 默认 | 作用 | 调整建议 |
|---|---|---|---|
| `rate` | 50 | 转发频率 Hz | 换有线后可提到 200（延迟 −15 ms） |
| `max_step_deg` | 3.0 | 每帧最大变化 | 上限速度 = `× rate`；加大更跟手但冲击大 |
| `alpha` | 0.4 | 一阶低通（越小越平滑越滞后） | 抖动大降到 0.2 |
| `deadband_deg` | 0.05 | 小于此变化不转发 | 一般不动 |
| `watchdog_ms` | 300 | 断流多久停发 | WiFi 差加到 500 |
| `init_max_diff_deg` | 15 | 开局姿态差上限 | 不建议放宽 |
| `max_vel_deg_s` | 600 | 判异常的角速度 | 手快可加到 900 |
| `passthrough_gripper` | true | 是否同步夹爪 | — |
| `joint_offset_deg` | 全 0 | 零位补偿（度） | 空间标定后填这里 |

**速度上限公式**

```
上限 = max_step_deg × rate
     3.0 × 50  = 150 °/s   （当前）
     3.0 × 100 = 300 °/s   （换有线后）
```

# 四、故障排查

| # | 症状 | 原因 | 处理 |
|---|---|---|---|
| 1 | `Package 'piper_teleop' not found` | 终端没加载环境 | `source ~/107/songlin/scripts/teleop_env.sh`；用 `ros2 pkg prefix piper_teleop` 自检 |
| 2 | `收不到关节数据` | 驱动没连上臂 | `sudo ~/107/songlin/scripts/can_up.sh`，确认有 20 帧 |
| 3 | `Device is DOWN` | socketcan 接口没 up（**不是臂坏**） | 同上 |
| 4 | 帧率只有几十~几百 | 接触不良 / 电源不稳 | 重插 CAN 接头；查 24V 指示灯是否常亮 |
| 5 | 有帧但报 `Failed to get firmware version` | 臂在 Leader 模式（`0xFA` 残留） | `cansend can0 470#FC00000000000000` |
| 6 | `move_home` 报成功但臂不动 | 驱动把"还没动"当"已到位" | 封装版已改用 `control/move_j`；手工版重复调用或改用 §2.7 的 topic 命令 |
| 7 | 桥报 `FAULT: 开局姿态差` | 两台差 >15° | 回零 / 对齐后 `ros2 service call /teleop_reset std_srvs/srv/Trigger "{}"` |
| 8 | 桥报 `FAULT: leader 角速度` | 拖太猛（>600 °/s） | 确认安全后 `teleop_reset` |
| 9 | 桥打印 `watchdog` | A 数据断流 >300 ms | 查 WiFi、A 机进程是否还活着 |
| 10 | B 不动，但桥在发 | 控制门闸没开 | `ros2 service call /follower/control_enable std_srvs/srv/SetBool "{data: true}"` |
| 11 | `ros2 node list` 只有一个驱动 | domain 或组播问题 | `echo $ROS_DOMAIN_ID` 应为 66；`ros2 daemon stop`；仍不行加 `ROS_STATIC_PEERS` |
| 12 | 关节读数超限/跳变（如 j4=−102°） | 帧类型不对，数值不可信 | `candump can0 \| awk '{print $2}' \| sort \| uniq -c`：有 `2A1~2A8` 才可信 |

# 五、限制与未做

| 限制 | 说明 |
|---|---|
| 末端绝对位置偏差 5–10 mm | 关节映射的固有代价，需笛卡尔映射才能消除 |
| 快速拖动跟不上 | 上限 150 °/s，超过就滞后 |
| WiFi 抖动大 | 位置遥操够用；力反馈必须换有线 |
| 空间未标定 | 两台零位差最大 5.37°（j5），目前靠回零，未做补偿 |
| 时间未同步 | 无 NTP/PTP，测不出真实延迟 |
| 夹爪同步未实测 | `passthrough_gripper` 代码就绪但没跑过 |
| 力反馈未做 | 见 `遥操作_v2_方案.md` |

# 六、安全隐患清单

| # | 隐患 | 后果 | 对策 |
|---|---|---|---|
| 1 | **`0xFA` 会被持久化** | 下次上电臂不进反馈模式，驱动连不上 | 只用物理拖动按键；已中招用 `0x470#FC` 恢复 |
| 2 | **无抱闸** | 断电/掉使能会下垂 | 停机时扶住；不要在悬空姿态掉使能 |
| 3 | **B 会跟随绝对姿态** | 姿态差大时 B 高速扫动 | 起桥前必须做 §2.5 姿态检查 |
| 4 | **速度上限 150 °/s** | 拖太快 B 追不上，滞后可达 50°+ | 正常操作 <50 °/s |
| 5 | **断网后 B 保持原位，A 仍在拖** | 两台姿态分叉 | 桥报 watchdog 时立刻停止拖动 |
| 6 | **B 的门闸默认关闭** | 忘了开会误判"桥坏了" | 用封装版（自动开） |
| 7 | **两台同时跑会抢 controller_manager** | 控制器全 inactive | 一套栈跑完再切另一套 |
