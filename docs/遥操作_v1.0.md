# 遥操作 v1.0 · 跨局域网主从镜像

> 版本：v1.0（方案阶段，未实施）
> 目标：手拖 A 臂，B 臂以相同姿态实时跟随
> 环境：两台电脑各接一个 USB-CAN，同一局域网

---

## 1. 范围

**做**：
- A（leader）进入零力拖动模式，手拖时输出实时关节角
- 角度经局域网转发到 B（follower）
- B 以相同姿态跟随，带限速、看门狗、零位补偿

**不做**（v1.0 明确排除）：
- 力反馈（leader 感受不到 B 的负载）
- 拖动示教记录/复现（那是另一套功能，见 §2）
- 视频遥操界面
- 多机（>2 台）编队

---

## 2. 术语：两个"示教"别混

SDK 里有两套完全不同的东西，v1.0 只用第二套。

| 功能 | SDK 接口 | 行为 | 遥操需要吗 |
|---|---|---|---|
| **拖动示教（记录/复现）** | `ArmMsgMotionCtrl(grag_teach_ctrl=0x01/0x02/0x03)` | 拖一遍 → 存轨迹 → 回放 | ❌ 不要 |
| **主从零力拖动** | `set_leader_mode()` (linkage 0xFA) | 拖动时重力补偿，**实时输出角度** | ✅ **用这个** |
| 跟随模式 | `set_follower_mode()` (linkage 0xFC) | 接收外部指令运动 | ✅ B 臂用 |

> 原生 0xFA/0xFC 的 linkage 走 **CAN 总线**，跨机器无效。
> 所以 v1.0 只借它的"零力拖动"能力，数据通道换成 ROS 2 网络。

---

## 3. 前提与约束

| 项 | 要求 |
|---|---|
| 两台电脑 | 都能跑 `~/107/songlin` 工作区 + ROS 2 Jazzy |
| Python 依赖 | 两边都装 `pyAgxArm`、`python-can` |
| CAN | 各自一个 USB-CAN，各自 `bitrate 1000000` |
| 网络 | 同一局域网，可互 ping；domain 独占 |
| 机械臂 | A 需要支持零力拖动（PiPER 系列支持） |

**驱动缺口**：`agx_arm_ctrl` 只暴露了 `exit_teach_mode`，没有"进入拖动"和"进入跟随"的入口 → 见 §5.A。

## 4. 架构

```
┌──────────────── PC-A · leader ────────────────┐
│  agx_arm_ctrl (+ 补丁)                        │
│    · set_leader_mode()  → 零力拖动            │
│    · 手拖 → 读关节角                          │
│         ↓                                     │
│  /leader/joint_states   (JointState @ 200 Hz) │
└───────────────────┬───────────────────────────┘
                    │  局域网 (ROS 2 DDS, domain 77)
┌───────────────────▼───────────────────────────┐
│  piper_teleop  (桥，跑在 B 机)                │
│    · 死区 / 限速 / 低通 / 看门狗 / 零位补偿    │
└───────────────────┬───────────────────────────┘
                    │
┌───────────────────▼───────────────────────────┐
│  PC-B · follower                              │
│  agx_arm_ctrl                                 │
│    · set_follower_mode()                      │
│    · /follower/control/joint_states → 运动    │
└───────────────────────────────────────────────┘
```

桥放在 **B 机**：网络只剩 A→B 一段，B 收到即执行，滞后最小。

## 5. 部件清单

| 服务 | 类型 | 调用 |
|---|---|---|

| `follower_mode` | `std_srvs/Empty` | `agx_arm.set_follower_mode()` |

> 不改就只能用"禁用状态拖"——没有重力补偿，拖着很重，不推荐。

### B · `piper_teleop` 桥（新包）

一个 Python 节点，参数化：

| 参数 | 有线默认 | **WiFi 默认** | 说明 |
|---|---|---|---|
| `src_topic` | `/leader/joint_states` | 同 | leader 角度来源 |
| `dst_topic` | `/follower/control/joint_states` | 同 | follower 命令 |
| `rate` | 100.0 | **50.0** | 转发频率 Hz |
| `max_step_deg` | 2.0 | **1.5** | 每帧最大变化，超出截断（限速） |
| `deadband_deg` | 0.05 | 0.05 | 小于此变化不转发（抑制抖动） |
| `alpha` | 0.3 | **0.2** | 一阶低通系数，1.0 = 关 |
| `watchdog_ms` | 200 | **300** | 超时无新帧 → 停止转发 |
| `joint_offset_deg` | `[0,0,0,0,0,0]` | 同 | 零位补偿 |
| `passthrough_gripper` | false | 同 | 是否转发夹爪 |

> 本方案按 **WiFi** 定参（用户确认两台连同一 WiFi）。
> WiFi 的丢包与抖动比有线大，所以频率减半、限速更严、看门狗更宽松。

输出前的处理链：

```
leader 帧
  → 加零位补偿
  → 一阶低通
  → 死区过滤
  → 限速截断（相对上一帧发出的值）
  → 发布
```

看门狗：`now - last_src_stamp > watchdog_ms` 时**停发**（B 保持最后位置），并打印告警。

### C · 环境脚本 `scripts/teleop_env.sh`

```bash
export ROS_DOMAIN_ID=77
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
```

两台都要 source。

⚠️ SUBNET 会看到实验室其他设备，domain 77 必须是你们独占。

**WiFi 补充**：很多 AP 默认丢弃组播，导致两台同 domain 也互相看不见。
若验证不通，追加静态对等节点（见附录 A.5）：

```bash
export ROS_STATIC_PEERS="对方IP"
```

## 6. 接口契约

| 方向 | 话题 | 类型 | 频率 |
|---|---|---|---|
| A 出 | `/leader/joint_states` | `sensor_msgs/JointState` | 200 Hz（驱动 `pub_rate`） |
| 桥 出 | `/follower/control/joint_states` | `sensor_msgs/JointState` | 100 Hz（`rate`） |
| B 出 | `/follower/feedback/joint_states` | `sensor_msgs/JointState` | 200 Hz（用于监控/对比） |

**关节名**：`joint1..joint6` + `gripper`（两边必须一致）。
**单位**：弧度。

> 注意：`control/joint_states` 是**整组下发**，缺的关节按 0 处理。
> 桥必须每帧发全 7 个名字，不能只发改动的。

## 7. 启动 / 停止顺序

**启动**（顺序不能反）：

```
1. B：起驱动 → enable → move_home → 确认全 0
2. B：follower_mode
3. A：起驱动 → enable → move_home → 确认全 0
4. A：leader_mode（此时臂变"轻"）
5. B：起 piper_teleop（先不转发，看打印）
6. B：teleop 开始转发（限速 5°/s）
```

**停止**：

```
1. 桥停（停发）
2. A：drag_restore（退出零力拖动，臂变硬）
3. B：保持最后位置；需要归位再 move_home
```

---

## 8. 状态机

```
IDLE
 └─ 两边回零、姿态差 < 0.5° ──► ALIGNED
ALIGNED
 └─ 桥开始转发 ──► TELEOP
TELEOP
 ├─ 无新帧 > watchdog_ms ──► FAULT(超时)
 ├─ 单帧变化 > max_step×3 ──► FAULT(跳变)
 └─ 人工急停 ──► FAULT(急停)
FAULT
 └─ 人工确认 + 重新对齐 ──► ALIGNED
```

FAULT 时桥**停发**，B 保持最后位置（位置模式下会锁住）。

---

## 9. 安全设计

| 风险 | 措施 |
|---|---|
| 网络抖动/丢包 | 看门狗 200 ms；B 保持最后位置 |
| 拖动过快 | `max_step_deg` 硬截断（不是软参数） |
| 两台零点不同 | 启动时都 `move_home`，桥里可加 `joint_offset_deg` |
| 单帧跳变（异常数据） | 单帧变化超过 `max_step×3` 判为异常，进 FAULT |
| 关节越界 | B 的 SDK 会静默 clamp 到限位（已知行为），桥侧也要预检 |
| 断网 | 同"网络抖动"，B 停住 |
| 无抱闸 | B 掉使能会下落；FAULT 后不要断电 |

---

## 10. 验收标准

| 阶段 | 内容 | 通过标准 |
|---|---|---|
| **v0** | 桥只打印，不转发 | 打印角度随手拖平滑变化，无跳变 |
| **v1** | 转发，限速 5°/s | B 跟得上，姿态肉眼一致，无抖动 |
| **v2** | 限速 30°/s | 滞后 < 0.3 s，姿态差 < 2° |
| **v3** | 夹爪同步 | 两边夹爪同开同合 |
| **v4** | 故障注入 | 拔网线：B 停在原位不失控；重连后需重新对齐 |

**姿态差测量**：同时 echo 两边 `joint_states`，逐关节算差值。

---

## 11. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| DDS 跨机丢包 | 默认 FastDDS 在 WiFi 上不稳 | 优先有线；必要时换 CycloneDDS 并配大 buffer |
| 两台固件不同 | 关节响应增益差异 → 抖动 | 限速 + 低通；避免高速 |
| 时钟不同步 | 时间戳不可用于同步 | 只用"最新帧"，不做时间对齐 |
| 桥崩溃 | B 停住不再跟随 | systemd/守护；桥退出时主动停发 |
| 拖动噪声 | leader 手抖直接传给 B | 死区 + 低通 |

# 附录 A · ROS_DOMAIN_ID 详解

## A.1 它解决什么问题

ROS 2 **没有中心节点（master）**：节点靠 DDS 自动发现、点对点通信。

后果是：实验室里多套 ROS 2 会互相"看见"，话题/服务混在一起
（之前那个 `piper_driver` 就是这么跑进我们话题里的）。

domain id 就是分区，像对讲机频道：

```
频道 0 :  [你的A] [你的B] [隔壁piper_driver] [别人的mujoco_arm]   ← 混在一起
频道 77:  [你的A] [你的B]                                        ← 只有你们
```

## A.2 底层：域号直接决定 UDP 端口

```
port = 7400 + 250 × domain_id + 偏移
```

| domain | 端口范围 |
|---|---|
| 0 | 7400 ~ 7650 |
| 42 | 17900 ~ 18150 |
| 77 | 26650 ~ 26900 |

同 domain = 同端口段 = 能互收；不同 domain 是**物理隔离**，不是过滤——真听不见。
范围 **0~232**。

## A.3 发现机制：组播 vs 单播

| 方式 | 地址 | 默认 | 问题 |
|---|---|---|---|
| 组播 | `239.255.0.1` 等 | ✅ 开 | **WiFi AP 常丢弃组播** → 同 domain 也看不到 |
| 单播 | 对方 IP | 需显式配 | 最可靠，但要固定 IP |

## A.4 怎么选号

| 规则 | 原因 |
|---|---|
| 两台**同号** | 否则永远看不见 |
| 不与实验室他人冲突 | 否则互相干扰 |
| 尽量不用 0 | 所有人的默认值，必撞 |

建议：50~200 之间挑一个没人用的。本方案用 **77**（可改）。

## A.5 验证与排障

```bash
# 两台都执行
export ROS_DOMAIN_ID=77
export ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
ros2 daemon stop
ros2 node list
```

| 看到什么 | 结论 | 处理 |
|---|---|---|
| 两台的节点都在 | ✅ 通了 | 继续 |
| 只有本机 | 跨机发现失败 | 见下 |
| 有陌生节点（piper_driver 等） | domain 撞了 | 换号 |

**跨机发现失败的处理顺序**：

1. 先 `ping` 对方 IP，确认网络通
2. 加静态对等节点（绕开组播）：
   ```bash
   # A 机
   export ROS_STATIC_PEERS="192.168.1.23"      # B 的 IP
   # B 机
   export ROS_STATIC_PEERS="192.168.1.101"     # A 的 IP
   ```
3. 仍然不通：查防火墙（`sudo ufw status`），放行 UDP 7400-26900

## A.6 `ROS_AUTOMATIC_DISCOVERY_RANGE`

| 值 | 范围 | 用在哪 |
|---|---|---|
| `LOCALHOST` | 仅本机 | 单机调试（防实验室干扰） |
| `SUBNET` | 整个网段 | **遥操必须** |
| `SYSTEM_DEFAULT` | 通常 = SUBNET | — |
| `OFF` | 关闭自动发现 | 只用 static peers 时 |

⚠️ 现在 `scripts/env.sh` 设的是 `LOCALHOST`（为了真机安全），
**遥操不能沿用**，必须单独设 `SUBNET`。

## B.2 在 `_exit_teach_mode_callback` 之后追加三个回调

```python
    def _leader_mode_callback(self, request, response):
        """进入零力拖动（leader）：电机只抵消重力，可手拖，实时上报角度。
        注意：调用前必须先 enable——零力也需要电机出力抵消重力。"""
        try:
            if not self._check_arm_ready():
                self.get_logger().warn("arm not ready, cannot set leader mode")
                return response
            self.agx_arm.set_leader_mode()
            self.get_logger().info("Leader mode ON (zero-force drag)")
        except Exception as e:
            self.get_logger().error(f"set leader mode failed: {e}")
        return response

    def _follower_mode_callback(self, request, response):
        """进入跟随模式（follower）：接收 control/joint_states 并按位置运动。"""
        try:
            self.agx_arm.set_follower_mode()
            self.get_logger().info("Follower mode ON")
        except Exception as e:
            self.get_logger().error(f"set follower mode failed: {e}")
        return response

    def _restore_drag_callback(self, request, response):
        """从受控状态恢复为零力可拖（leader 回零后必须调一次）。"""
        try:
            self.agx_arm.restore_leader_drag_mode()
            self.get_logger().info("Leader drag mode restored")
        except Exception as e:
            self.get_logger().error(f"restore drag mode failed: {e}")
        return response
```
